#Security Architecture & Secret Hygiene Guide

Target Audience: Biblion Core Engineers, DevOps & Security Reviewers

Authors: Biblion Evangelist in cooperation with Code Reviewer / Auditor & Biblion DevOps/SRE

#1. Non-Negotiable Standing Security Rules

  1. Zero PII / Identifier Leakage:

> ABSOLUTE RULE: SSN digits, tax IDs, and comparable personal identifiers must NEVER be transmitted over the network — not in tool output, not in scripts, not in database seeds, and not in command echoes.

  1. Payment Card Industry (PCI) Compliance:
  • Credit card numbers, expiration dates, and CVCs are handled strictly client-side by Lemon Squeezy hosted fields.
  • Neither biblion-app nor biblion-api ever inspects, logs, or stores cardholder numbers.

#2. Secret & Environment Management

  • Local Development:
  • biblion-api/.env holds development credentials and is excluded via .gitignore.
  • Template variables are tracked safely in .env.example.
  • Production Droplet Secrets:
  • Secrets live at /etc/biblion-api.env (accessible only by root and biblion user with permissions 0600).
  • Symlinked into /var/www/biblion-api/shared/.env.
  • Never commit API keys, master encryption keys, or database passwords to Git.

#3. Webhook Cryptographic Verification

  • Every inbound webhook from Lemon Squeezy (POST /webhook) is validated using HMAC-SHA256 signatures with LEMONSQUEEZY_WEBHOOK_SECRET.
  • Requests failing signature verification are rejected with HTTP 401 Unauthorized before any database lookup occurs.

#4. Pre-Commit Review & Security Gates

Before merging any branch into main:

  1. Verify clean Git status across repositories.
  2. Audit dependencies for known vulnerabilities:

```bash

npm audit --prefix biblion-app

bundle exec bundle-audit --gemfile biblion-api/Gemfile

```

  1. Run Brakeman static analysis on Rails API to detect SQL injection or mass-assignment risks.
